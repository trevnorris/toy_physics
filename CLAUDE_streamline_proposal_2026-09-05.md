# Proposal: make review scope explicit, preserve every control

## 1. Diagnosis

The list mixes artifact scope, timing, review composition, stopping criteria, and evidence inside the same numbered units: rule 7 moves from “Two legs on anything physics-bearing” to “its decision list” to “One pass, then fold and go” without explicitly closing the exception (C38–47), while the stopping criterion appears separately in rule 10 (C52–54). That structure permits the reported decision-list → `SHARED_PHYSICS` misapplication; the incident is supplied by the task, not recorded in C. Other overloaded terms invite similar transfers: “whatever writes does not review” coexists with “verify it myself” (C38,65), “never what anything equals” with “Supply everything else, as equations” (C30–32), and “The commit is the last step” with the build skill's requirement to commit a reviewed baseline before repair (C50–51; B171–176). Controls also recur at different levels—computed output, evidence for orchestrator claims, and executable review (C11–23,66–70)—without a single scope index. Finally, terse instructions interrupt and are interrupted by measured failures (especially C14–23,41–47,75–81). Preserve that evidence, but separate it visually from executable instructions and expose artifact class, reviewer authorship, gate, and exit condition together.

This separates presentation, not authority: the full controls and evidence remain in the governing document. ### Six-line quick reference

1. **Identify object and artifact role.** Supply verified equations; withhold target-answer criteria; construct independently; preserve disagreement. (C9–10,24–34)
2. **Measure claims.** Compute and emit before guards; interpret in records; attach commands/stdout; repair broken instruments. (C11–29)
3. **Select two non-author legs.** Orchestrator → Codex + Grok; Codex → fresh Claude + Grok. Launch before inspecting results. (C38–40,48–51)
4. **Use the right exit.** Decision list: two legs, one fold before builder launch. Physics spec/script/record: review-until-clear about computation and claims. (C41–43,52–54)
5. **Verify and preserve.** Adjudicate findings by evidence; ablate physics checks; keep varying quantities live; change defect-breeding author; no commit before both reports. (C50–52,65–81)
6. **Enforce, do not merely promise.** Bound handoffs and retain visible evidence; do not restore quarantine or drop controls for cost. Follow annex retrieval/publication policy for v3 `.out`. (C58–64,83–101)

### Example: current rule 7 rewritten

> **G1 — Two independent legs; authors never fill their own review slots.**
>
> **Applies to:** every physics-bearing artifact, including the spec both engines read. Select reviewers by actual authorship: orchestrator-written → Codex + Grok; Codex-written → fresh Claude agent + Grok. Record mixed/changed authorship and establish a valid non-author pairing before proceeding. Personal verification of findings is required but is never a leg.
>
> **G2 — Decision-list gate, and only the decision-list gate.** Before launching any builder, send its orchestrator-written decision list to Codex + Grok. Receive both reports, verify findings, and fold once; do not iterate this list review to green. If the packet also governs physics as a spec, apply the spec gate independently: review-until-clear under G4. The one-fold instruction cannot authorize a build with unresolved material physics decisions.
>
> **Advance only with:** identified artifact/version and role; author and reviewer identities; both attributed reports; evidence-backed finding dispositions; the folded list; applicable spec clearance. Downstream build and record reviews remain separate. Launch reviews before result inspection and permit no commit before both reports.
>
> **Evidence E7 — preserve as quoted evidence, not prompt boilerplate:**
> “Measured 2026-08-09: six spec defects, each costing a build round *plus* two legs, when two legs before the build would have caught them — three "level-above" misses, one exception named instead of the property (which bred a regression), measured counts stated four lines above "do not state the counts", and **an acceptance test that would have passed with the defect still in place.**” (C44–47)
>
> **Sources / companion controls:** C38–43 (coverage, pairing, list exception); C48–54 (timing, separate build tax, exit); C65 (verification); C71–72 (author change); L79–94 (authorship, not file type). The added explicit role boundary and manifest fields implement A1–5; they are proposed clarifications, not quotations of existing text.
