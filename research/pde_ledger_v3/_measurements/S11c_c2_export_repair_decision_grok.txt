## 2. R1 membership

**Finding: exporting both closed operators (all 4 cases) and making the increment EMIT-only is correct per D1.** Not under-export; residual over-export risk is the one D1 already accepts while S11c-d is unbuilt.

**S11c-d needs both, not one.**

Resonances / local spectrum are properties of the **closed full operator**, not of the off-diagonal block alone.
- Spec §2 (SHARED_PHYSICS.md:137–138): closing threads `Z` through the operator **including the transverse diagonal**. The frozen parent `slab_operator` is still the open/pressure-slot operator. Re-closing at consume time is forbidden (export_ledger_bind_closure_design.md:134: “Never a PY re-derivation of an inherited object at consume time”).
- Spec §3b (SHARED_PHYSICS.md:189–196): `s11cc2ClosedCouplingKernel` is the re-extracted **off-diagonal** block — what a Born / linear-mixing / leakage calculation binds. N1 again bars d from re-extracting it.
- Therefore: slab operator for the closed spectral equation; coupling kernel for mixing/Born. The original c2 build directive already stated this (S11c_c2_sympy_build_directive.md:197–208) and noted d has no `IMPORT_KEYS` yet.

**The increment is genuinely a non-binding comparator representation.**

- Spec §3c (SHARED_PHYSICS.md:214–215): “This is an **export representation**, ⛔ not a residual check.” It drops the bulk/kinetic base (:216–218) and exists so the T7 comparator can join stdout.
- Adjudication (S11c_c2_physics_review_adjudication.md:49–51, 108–111): the increment is not the S11b-decoupled self-energy; STEP B already dropped it to EMIT-only.

`term_origins` / parity / §3d / §5 / increment-operands are already *not* in `EXPORT_ROOTS` (only the three named keys are in the map at script:894–896). The directive is making that explicit, not newly cutting them.

**Over-export?** If d later binds only one of the two operators, the unused one is a D1 flag at d-build time (already recorded at S11c_c2_sympy_build_directive.md:207–208). Exporting only the kernel would **under-export** the closure-modified diagonal. Exporting only the slab operator would force d to re-extract, which D1/N1 forbid.

## 3. R2 representation — **MUST-FIX**

**Finding: the goal (transparent compact, importable, differentiable, semantic identity) is right. The stated method is not sufficient on the real payload, and CSE as a stored form is unsound.**

### What is actually stored

Each export root is **one key holding all four cases**, not four keys. The row `value` is `cas({case: emit_payload})` (script:874, 893–898, 952), and each emit payload is (script:754–759):

`VALUE`, `MULTIGRADE`, `DIMENSION_L_T_M`, plus `COMPUTED_BRANCH_BINDINGS` / `FOURIER_PROFILE_BINDINGS`.

A downstream `load_model` consumer will parse it the way this engine already parses parents: `fold[key]['value']` then `cases()` → `named(v, 'VALUE')` (script:178, 84–85). `cases()` **requires** that Tuple-of-(case, VALUE-record) shape. Replacing the row with a bare factored operator, or with a CSE `(replacements, reduced)` pair, would make the kernel unbindable even if algebraically related.

Measured: `s11cc2ClosedCouplingKernel` 24 740 899 bytes, `s11cc2ClosedSlabOperator` 19 859 799 bytes, both starting `Tuple(Tuple(Tuple(Str('LAB_HELD'), Str('RHO4_CONSTANT')), Tuple(Tuple(Str('VALUE'), …`.

### CSE is not a legal stored form

`sp.cse` returns dummy replacements plus a reduced expression. Those dummies are not in `NEW_DIMENSIONS` (script:52, 119–136), so `check_consumer` treats them as free/structural (ledger_fold.py:241–242: zero identity rows → skip). A later `diff` on the stored value then differentiates an incomplete CSE skeleton, not the operator.

srepr does not preserve DAG sharing: CSE-then-substitute-back does not shrink the file. CSE only shrinks the file if the replacement table is stored — which is exactly the “opaque wrapper / string that only re-parses” the directive forbids (directive:39–40).

`factor` / `cancel` / `together` / `collect` remain valid **if they stay one expression of the same type as the emitted leaf**.

### The written zero-test does not apply to this object

`sp.expand(decoded_compact − emitted_expanded) == 0` (directive:41–42) subtracts two **cased Tuples**. SymPy will not do the elementwise operator compare `difference()` already implements (script:100–109). The physics adjudication already showed the related failure: `expand` leaves `Integral(0,…)` unevaluated (S11c_c2_physics_review_adjudication.md:47). These operators are Integral-rich (Fourier / DtN). A top-level `expand(A−B)` will either false-hard-stop or miss integrand drift.

“Or an equivalent canonical zero-test” is too loose: the previous builder already ignored a compact-form requirement. The formula in the directive is the one they will copy.

A factored **leaf** remains importable and differentiable: `_restore` evals srepr into a real `sp.Basic` (generated file header; ledger_fold.py:51–65), and `factor`/`collect` do not wrap `UnevaluatedExpr`. The silent-loss cases the leaf check **would** miss are: dropped symbol assumptions, `Eq(evaluate=False)` vs evaluated `Equality`, and Integral-representation changes that `expand` does not enter. Walking leaves with the existing Integral Dummy-protection (script:106–109) closes the last of those.

**Nit (same heading).** “Upgrade” the srepr `==` roundtrip (script:848–851) should **not** delete it. That check is serialization fidelity of the compact form. Add the semantic leaf test against the emitted object; keep `_restore(compact) == compact`.
