The reviewed numerical equations, windows, precision, rules, tolerance and analytic tail policy remain fixed. The only mathematical work requested after recovery is the original unfinished numerical tail.

## Exact recovery state sequence and numerical wrapper contract

The prototype operates only on already encoded JSON. It does not call a numerical decoder or evaluate an integral. The future wrapper supplies encoded callbacks and must obey this exact sequence:

1. **PARENT.** The first numerical request must be exactly the pre-registered record 1, namespace and receipt. A wrong byte fails before begin or callback. Claiming sets state NODE and invokes only the unfinished parent callback. A fresh ordinary request is unavailable here.
2. **NODE.** The first put must be `outer-node-input` in A24/baseline. Compare its entire encoded payload against actual record 2 and reread that original receipt. On exact match, return the original receipt and **skip** the put and serial increment. Append an explicit verified-skip event to the recovery ledger. Any other name, point, argument or input refuses. This selects one deterministic policy; the old node is not duplicated under a new name.
3. **CHILD24 then CHILD48.** Both full child descriptors are fixed in advance, including actual route A24/precision30 and selected inner rule A24 or A48. At each step require byte identity with that specific witness, look up its completed return and compare original input/return receipts. A miss, wrong order or changed descriptor raises before begin or callback. Neither supplied child callback can execute. Record both complete reuse links.
4. **PAIR.** No new request or namespace is permitted. The next numeric put must be `inner-positive-panel-pair`. It must contain the exact two restored full panels with string evidence keys, original a/b, cell and ownOrder24, plus the complete reconstructed component census. The original unchanged scalar expression creates the component values; the prototype does not independently recalculate them. `before_put` validates inputs but does not release the state. Only `after_put`, after reading back the complete committed receipt and payload at a new sequence/name581, changes state to NEW. A failed put leaves the state unreleased.
5. **NEW.** The original request behavior is available for unfinished work, including exact completed lookups and new requests. Other pending requests still refuse. When the original parent callback finally returns, require the prefix state NEW, complete its original ticket once and record the new return/old-child provenance. An early callback return cannot publish a parent result.

The future numerical wrappers have a narrow interface. `ns` constructs the original descriptor and calls `protocol.namespace` before insertion. For every original A24 baseline and A24 formula-check:baseline route, it must match the exact pre-existing namespace, even after state NEW; no different namespace for those keys may be silently inserted. A new route/purpose can be inserted only after recovery of the first pair. `request` constructs the original full descriptor, supplies a callback that applies the existing encode to new results, then decodes the protocol's returned JSON in the original own context. `put` encodes first, calls `before_put` before incrementing the serial, returns the old receipt for the verified skip, or uses the original serial/write path followed by `after_put`. None of these hooks changes the mathematical callback body. The complete build must show these actual call sites and test the integration, not merely import an unused helper.

Manufactured tests make completed-child callbacks raise if invoked, patch begin to refuse any forbidden path, mutate first parent/child/namespace/point/cell/route/rule inputs, exercise a completed-child lookup miss, and require actual pair publication before new work. These are tooling tests, not proof of the future native integration. The prototype snapshots failed prefix operands before decisions; final records include those exact attempts and state, not just a failure string.

The future worker must persist `final_record` and all source/DB/tree posthashes from independent finally paths even after an exception. It must verify the original empty leaf table at admission; legitimate newly computed adaptive leaves may be added later, so finalization does not require the entire new leaf table to stay empty. Every original namespace row and all immutable prefix rows remain exact, with no generic hash exception. Current leaf count and old/new sequence ranges are recorded. Any preservation failure remains fatal, distinct from a numerical result.
