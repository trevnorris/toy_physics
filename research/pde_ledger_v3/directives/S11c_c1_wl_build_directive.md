## The three script clauses and the structural rule (spec §6 — exact obligations, both engines identical)

1. **A script prints computed CAS objects and never states conclusions.** An emit payload is a CAS object — an
   expression, a solved root, a typed boolean with its operands — ⛔ never prose describing a result, ⛔ never a
   hand-typed CAS object with no data dependence on the derivation (build-skill corollary 1), ⛔ never a name that
   gives away the value/ratio/sign/shape (corollary 2).
2. **For every comparison emit operand A, operand B, and `A−B` before any guard.** A physics disagreement emits
   and continues with **exit status 0**; nonzero exit is reserved for operational failure only. ⛔ No
   tautological residual (`A ≔ B/C` then `A·C − B`): where no second route exists, emit the objects and say so.
3. **Interpretation belongs to the step record, not the engine.** ⛔ No terminal `VERDICT`, `PASS`, `FAIL`. A
   growing or decaying root, a real or imaginary impedance/kernel part, is emitted as the object the computation
   returns — ⛔ never suppressed, re-branched, or reclassified to reach a passive or lossless form (spec §1b/§6).

Emission is **never conditional on a payload's value**; a boolean-valued test is emitted **as the typed CAS
object retaining its operands** — the unevaluated relational (e.g. `Inactive[Equal][a, b]`), the `STATUS_TOKEN`
of the §6 locus protocol, the noninvertibility relational — ⛔ never a host-language native or evaluated boolean
(`True`/`False`), **because the downstream frozen T7 comparator rejects a native boolean as a residual operand**
(a native-boolean leaf scores boolean-vs-number as a false AGREE); this is on the critical path for c1's
`WL_S11CC1_DEGENERATE_LOCI_*` and `WL_S11CC1_NONINVERTIBILITY_CONDITION`. A value present and identical across
cases = an INVARIANT (a real finding); a value absent = indistinguishable from never-computed. Tag **names** are
unique; payloads may legitimately repeat.

**The structural rule (spec §6, verbatim, binding):** physical symbols may be combined by hand **only** in the
supplied setup, background ansatz, face maps, bulk acoustics, radiation condition, and supplied laws in §§1–2.
**Every §3–§5 expression is reached by computation.** Every control re-enters at an ansatz, map, level set, bulk
operator, radiation condition, or supplied law, **⛔ never at a result.**

## Run discipline — binds the build's own demonstration runs (`CLAUDE.md`; `[[feedback_mathematica_single_seat]]`, `[[feedback_background_tasks_can_die_spuriously]]`)

⚠ These constrain **how the build runs**, not what it computes — ⛔ they drop no object, narrow no case, and never
condition emission on a payload's value (rule 11: correctness is king).

- **The licence has TWO seats — run at most ONE kernel at a time**, and ⛔ never more than 2 concurrent kernels
  across everything on the box. Serialize anything that spawns kernels.
- **`--sandbox danger-full-access`** (Mathematica needs it — `[[feedback_codex_mathematica_sandbox]]`).
- **Kill criteria, by PID, recorded and reported — ⛔ never answered by narrowing or cheapening the requested
  object:** **600 seconds with NO new stdout** (the rule is *observable progress*, not elapsed time — a streaming
  task may legitimately run long, `[[feedback_script_timeout_policy]]`), **or** resident memory past a recorded
  ceiling. ⛔ Do **not** wrap the run in a shell `timeout` (SIGKILL has cost 300k+ tokens); watch the marker/RSS
  instead.
- **The build launch is DETACHED** — `setsid nohup bash -c '…; echo "EXIT=$? …" > MARKER' < /dev/null & disown`
  from a foreground call, with a Monitor watching the **marker file** (⛔ not `pgrep -f`, which matches the
  wrapper). The harness reaps `run_in_background` Bash tasks at ~87 s; a naive `run_in_background` launch of a
