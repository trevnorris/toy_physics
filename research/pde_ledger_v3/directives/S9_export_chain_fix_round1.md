## F-1 · `dim` is manufactured, and the one object that needs it has none

**Measured.** 21 entries carry a `dim`. **19 of them are `srepr`-identical to that entry's own `value`** —
`dim_terms` carries the Lagrangian's terms as its "dimension", `dim_linear_system` carries equations,
`dim_solution` carries a solver substitution dict. The field is selected by whether the name string starts
`DIM_`, not by what the dimension solve produced. And the in-run roundtrip compares `value` against
`record["dim"]`, so it **enforces the tautology it should be catching** — `EXPORT_ROUNDTRIP_RESIDUAL: 0`
currently asserts that `dim == value`.

Meanwhile `transverse_speed_squared` — the light cone, the object the whole sector rests on — carries **no
`dim`**, although the same run computes a dimension for it.

**Fix.** `dim` is the dimension the engine's own solve produced **for that object**, looked up by the
object, not passed the value. Where the solve produced no dimension for an object, the entry has **no
`dim`** — the directive's rule stands: no `None` as though it were a result, no "dimensionless", and above
all nothing manufactured. An object that *is* a dimension does not thereby *have* one.

Remove the `value`-against-`dim` comparison from the roundtrip residual. The roundtrip's job is exact
reconstruction of what was written; it is not a dimension check.

Report the new counts and say which objects carry a dimension.

## F-3 · The Python mapped diff cannot fail on the seven new names

**Measured.** The Wolfram side maps all twelve renames and excludes nothing, so its exit 0 genuinely
demonstrates rename-only. The Python side maps five and `rg -v`-excludes seven. Corrupting all seven at
once — light cone to `-1`, multiplicity to `7`, route residual to an all-ones matrix — still exits **0**.
Five of the seven have a baseline counterpart under a different name and could have been mapped exactly as
the Wolfram side maps them. One object, the flexural scaling residual, was mapped on one side and excluded
on the other.

**Fix.** Map on the Python side every object that has a baseline counterpart, whatever its name. Exclude
only what genuinely has no baseline predecessor, and list what you excluded and why. **Then show the check
failing**: corrupt each previously-excluded payload in turn on a scratch copy and report the exit code.

## F-4 · `class` and the knob list are typed literals, so the export cannot be the knob frontier

**Measured.** `write_exports()` hardcodes `"KNOB"` for a two-element tuple and `"DERIVED"` for everything
else. Changing `mu_R`'s annotation from `KNOB` to `CONTROL` leaves both the engine `.out` and
`S9_exports.py` **byte-identical**. So two independent name→class mappings exist — the annotations and the
literals — and they drift silently.

**Why it matters:** D7 makes the export the record of what is still undetermined. A knob later derived from
substructure keeps reporting `KNOB`; a knob newly introduced never reaches the export at all.

**Fix.** `write_exports()` reads the class from the same annotated declarations `extract_knob_inventory.py`
reads, and enumerates the knobs from that scan rather than from a typed tuple. One source of class truth.

⚠ A leg also found that the export writer dies with `KeyError: mu_R` under a form ablation that changes
which coefficient carries the stiffness, because the knob tuple names `mu_R` literally. Reading the knobs
from the scan should remove that too; say whether it did.

## F-5 · The posited action is exported as `DERIVED`, and the export has zero premises

**Measured.** `LEDGER` is `KNOB: 2, DERIVED: 137`, **no `PREMISE` entries at all** — and among the 137 are
`lagrangian` (the curl-only MacCullagh action), `plane_wave_ansatz` and `assumptions`.

The `.wl` header calls it *"Supplied premise P5: the brane stiffness has the MacCullagh curl-only form."*
The plan's own annotation example marks that density `PREMISE`. The step record files it as postulated and
warns that reading *"light requires shear"* as established by this computation is stronger than the
computation supports. Both legs' form ablations confirm it: swap the stiffness form and the answer swaps.

**Why it matters:** the knit phase reads this generated file to learn what S9 established. As written it
would read that S9 **derived** the curl-only form. S9 postulated it — that is the step's central premise
and its live falsifier.

**Fix.** Class comes from the annotation (F-4), and the posited action, the ansatz and the assumption set
carry `PREMISE`. Report the resulting class tally.

## F-6 · Two of the twelve compare zero against zero

`DYNAMICAL_MATRIX_ROUTE_RESIDUAL` and `SPEED_DIMENSION_DIFFERENCE` are each engine's **own** internal
residual, already zero when emitted. Comparing them across engines measures that two zeros are equal. One
of them stayed the zero matrix under **every** ablation a leg ran.

**Fix.** Keep emitting them — they are honest engine outputs and rule 2 wants operands and residuals
printed. But they carry no cross-engine information about any physical value, so **any count of
cross-engine agreement must exclude them and say so.** ⛔ Do not report `12/12`.
