## 1 · Annotate every declaration

Every symbol declared in `S9_light_requires_shear_sympy_audit.py` carries a class tag and an English
description, on the declaration line:

```python
rho_br = sp.Symbol("rho_br", positive=True)   # KNOB · brane inertia density · not derived here
D      = sp.Symbol("D", integer=True)         # STRUCTURAL · brane spatial dimension
kx     = sp.Symbol("kx", real=True)           # COORDINATE · wavevector component
mu_G   = sp.Symbol("mu_G", positive=True)     # CONTROL · bare-field ablation coefficient
```

Grammar (**D8**): `# TAG · English description`, one tag per declaration, nothing else on the line.
Closed class set: `KNOB` · `STRUCTURAL` · `COORDINATE` · `CONTROL` · `PREMISE` · `DERIVED`.

**Line 19 must be split.** `rho_br, mu_R, rho_z, mu_F, mu_G = sp.symbols(...)` declares symbols of **two
different classes** in one statement, so one tag per declaration is unsatisfiable without splitting it.
Where a grouped declaration is class-uniform (`t, x, y, z`), one tag on that line is correct — do not split
it for uniformity's sake.

The three field heads `u1, u2, u3` (`sp.Function`) are declarations and get a tag.

### An annotation must NEVER contain what the computation will produce

**No value. No dimension. No count. No sign.** Not in a comment, not in a docstring, not in a variable
name.

This is measured, repeatedly, in this project: once an expected result is written where a builder can read
it, the builder iterates until the computation matches it, and the check degenerates into two copies of an
assumption agreeing. **Make the script correct; read the answer afterwards.**

An *inserted equation* is allowed, because it is an input under test rather than a result:

```python
# PREMISE · stiffness density posited as curl-only
stiffness_density = mu_R * curl(u).dot(curl(u)) / 2
```

## 2 · The named collection already exists — reuse it, do not build a second one

The plan's step 2 asks that end derivations land in a named collection. **A review leg measured that they
already do**: `all_outputs["MAIN"]` holds them, and the emit loop's boundary is exactly its non-underscore
entries — 132 objects today.

**D1 — the boundary is package membership**, and it is determinate: `MAIN` is a literal key of `actions`,

filter `emit` already applies. The control packages `X1`–`X8` are ablation evidence, not exports. S9 has no
`LOCAL_` convention (an S11 innovation, unavailable here), so `MAIN` membership is the whole rule.

⚠ **Generate `S9_exports.py` by iterating that same collection.** Do **not** build a second
name→object mapping and populate the export from it. A second mapping is exactly the failure this whole
pivot removes: a review leg constructed the case where the `.out` is unchanged while an export entry is
bound to a *different* live object, and every check in this directive passes. Iterating the emitted
collection makes that class of defect unrepresentable rather than merely unlikely.

**D2 — the collection's internal form is otherwise yours to choose.**

## 3 · Generate `scripts/S9_exports.py`

Written by the run, at the end of the run. **Never hand-edited.**

**D5 — the shape is FLAT, not nested by step:**

```python
# S9_exports.py — GENERATED by S9_light_requires_shear_sympy_audit.py. Do not edit.
LEDGER = {
    "rho_br":               {"value": ..., "dim": ..., "class": "KNOB",    "step": "S9"},
    "factored_determinant": {"value": ..., "dim": ..., "class": "DERIVED", "step": "S9"},
}
```

Each later step will import the previous step's `LEDGER`, add its own entries, overwrite what it derives,
and export the merged flat dict — so `LEDGER["x"]` is the current value of `x` with no sections to walk.
The `step` field records who last set the entry.

- **D3 — reconstruction must be exact.** Write each value in a form SymPy reconstructs exactly, and
  **verify the round trip inside the run**: reconstruct what you wrote and compare it against the live
  object. Carry a human-readable rendering alongside it — hand-checking this file is an intended use, so it
  must be readable by a person. (A leg executed `srepr`/`eval` against all 132 current `MAIN` payloads with
  zero failures, so this is known buildable.)
- Carry the step's **knobs** — symbols consumed and not derived — with their class tags.

### The `dim` field — present when the engine computed one, ABSENT when it did not

**Both legs found that D1 and "every export carries a dimension" cannot both hold.** Measured: `MAIN` emits
**132** objects and the dimension solve produces a dimension for **17** of them. Objects like
`LAGRANGIAN`, `ROOT_E1` (a list of booleans), `ASSUMPTIONS` and the mixed diagnostic tuples have no single
dimension in the solver's output, and several could not have one without inventing a nested schema.

**The rule, and it is not a licence to invent:** `dim` carries whatever the engine's own dimension solve
produced for that object, in whatever shape it produced it (**D4** — do not reformat, normalise or re-type
it). **Where the solve produced nothing, the entry has no `dim`.** Do not write `None` as though it were a
computed result, do not write "dimensionless", and above all **do not manufacture a dimension** — a field
whose only honest value would be invented is worse than an absent field.

Report the count: how many exported entries carry a computed dimension and how many do not.

Every dimension in this project is **computed**. None is declared.

`S9_exports.py` is committed. Nothing imports it yet — S10 is a later pass.

## 4 · Names — both engines emit the standard name of the object (D11)

**A name belongs to the object, not to the engine that computed it. Neither engine is the authority.**

The deleted registry recorded the standard name of twelve S9 objects in its `quantity:` field. Retrieve the
original context if you want it:

```
git show 67dd3ce2:research/pde_ledger_v3/reduction/checks_S9.yaml
```

### Two correspondences that hold everywhere — state them once, apply them throughout

- **`omega2` is not `omega`.** SymPy carries the squared frequency as a **single symbol** `omega2`; Wolfram
  writes `omega^2`. Any cross-engine value comparison needs this identity. It is a property of the two
  engines, not of any one row.
- **A dimension vector is a length-3 sequence.** Wolfram renders it as a `List` (`{-D, 0, 1}`), SymPy as a
  3×1 `Matrix`. **That is one object in two type systems**, not a disagreement, and it covers every
  dimension row below.

### The twelve, in three groups — the group decides what you do

**Group A — direct renames.** Both engines already emit the object itself. Rename both.

| standard name | Wolfram tag today | SymPy tag today |
|---|---|---|
| `FACTORED_DETERMINANT` | `WL_S9_DETERMINANT` | `PY_S9_MAIN_DET_M_FACTORED` |
| `FULL_ROOT_MULTISET` | `WL_S9_ROOT_MULTISET` | `PY_S9_MAIN_ROOT_MULTISET` |
| `INERTIA_COEFFICIENT_DIMENSION` | `WL_S9_RHO_DIMENSION` | `PY_S9_MAIN_DIM_PRIMARY_INERTIA` |
| `STIFFNESS_COEFFICIENT_DIMENSION` | `WL_S9_MU_DIMENSION` | `PY_S9_MAIN_DIM_PRIMARY_STIFFNESS` |
| `COEFFICIENT_DIMENSION_DIFFERENCE` | `WL_S9_MU_RHO_DIMENSION_DIFFERENCE` | `PY_S9_MAIN_DIM_STIFFNESS_MINUS_INERTIA` |

⚠ The old config called row 2 a *set*. **It is a multiset** — the transverse root appears twice in both
payloads, and the config's own comparison mode said `multiset`. The name is corrected here; do not let a
reader infer set semantics from a duplicated payload.

**Group B — SymPy emits a container; Wolfram emits the object.** SymPy must **also** emit the component
under the standard name. **Keep the existing container tag under its existing name** — that is mandatory,
not "if useful": D1 exports it and the baseline comparison requires it to survive unchanged.

| standard name | Wolfram tag today | the object SymPy must emit under it |
|---|---|---|
| `TRANSVERSE_MULTIPLICITY` | `WL_S9_ROOT2_E2` | the E2 multiplicity of the transverse root |

| `DYNAMICAL_MATRIX_ROUTE_RESIDUAL` | `WL_S9_DYNAMICAL_MATRIX_RESIDUAL` | the residual between the two route operands |
| `BARE_FIELD_COEFFICIENT_DIMENSION` | `WL_S9_X8_MU_G_DIMENSION` | the dimension of `mu_G` |

These name the **object**, not a recipe. Do not read them as instructions to index a particular position —
find the object in your own structure and emit it. ⚠ Row `BARE_FIELD_COEFFICIENT_DIMENSION` is the one a
builder can get wrong by position: SymPy's container holds `rho_br`, `mu_R` **and** `mu_G`, and the object
is `mu_G`'s.

**Group C — BOTH engines wrap.** Two rows. The legs disagreed here and the disagreement was adjudicated by
measurement:

```
WL_S9_SPEED_SQUARED_IMPLIED_DIMENSION: {{2, -2, 0}}
PY_S9_MAIN_DIM_SPEED_FROM_EXPRESSION:  [(mu_R/rho_br, Matrix([[2],[-2],[0]]))]
```

Wolfram's payload is a **list of dimension vectors, one per speed candidate.** SymPy's is a list of
`(candidate, dimension)` pairs. So a bare rename would put a shared name over unlike payloads — and D12
forbids repairing the Wolfram side.

**The object is the per-candidate dimension list.** Wolfram already emits exactly that. SymPy emits it
under the standard name — the same list, keyed the same way Wolfram keys it — and keeps its
`(candidate, dimension)` container under its existing name.

| standard name | Wolfram tag today | SymPy container to keep |
|---|---|---|
| `IMPLIED_SPEED_DIMENSION` | `WL_S9_SPEED_SQUARED_IMPLIED_DIMENSION` | `PY_S9_MAIN_DIM_SPEED_FROM_EXPRESSION` |
| `SPEED_DIMENSION_DIFFERENCE` | `WL_S9_SPEED_SQUARED_DIMENSION_DIFFERENCE` | `PY_S9_MAIN_DIM_SPEED_DIFFERENCE` |

**If you cannot make either row's shared name truthful without changing the Wolfram payload, do not rename
that row. Report it instead** — an untruthful lookup is worse than an unpaired object.

**Renaming beyond the twelve is a naming decision about physics objects and is not a builder's call.**

Where only one engine derives an object it simply has no counterpart. That is not a defect and **you must

### What may change in the `.wl` (D12)

**The emitted name string, and nothing else.** No change to the derivation, the action, the ansatz, the
