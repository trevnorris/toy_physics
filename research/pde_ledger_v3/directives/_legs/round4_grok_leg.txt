## Answers to the starred questions (before findings)

### 1 · Who writes a claim, and what catches a wrong one?

**Who:** the builder, at emission time (`D2`: “created with the live object”, never later by a map). A claim is **authored**, not computed from a dependency residual.

**How many for full MAIN?** Not a single a priori integer. The declared MAIN sweep is `D ∈ {2,3,4,5}` (4 cells). Root- and stratum-scoped claims are indexed by **computed** `ROOT_ORDERING` / `STRATUM_ORDERING` (`D8` admits this). Counts from the spec:

| Layer | Count basis |
|---|---|
| Fixed package-level roles (stub inventory) | ~65 × 4 D ≈ **260** |
| Root-scoped suffixes in the spec | **33** × Σₙ roots(D) |
| Stratum-scoped | **11** × Σ n_strata |
| Symbol claims | one per distinct `Symbol` atom (data-dependent) |
| Illustrative if 2 roots/D, 0 strata | **~524 tag-role claims** + symbols |
| S10 empirical MAIN floor (smaller Q set) | **426** dim-scoped rows already |

So a MAIN export is **O(10²)–O(10³) hand-authored claim trees**, not a handful.

**What catches a wrong claim?** **Nothing in this list.**  
`D8` checks **population presence** of claim trees, not whether the tree names the right defining inputs. `D5` only runs **after** a claim match. `D4`/`D6`/`D9` treat a well-formed wrong tree as ground truth.

**Mechanism wrong physics survives:** author the same claim for two different roles (or omit the action from both) → join merges them → equal payloads ⇒ `AGREE` and publish; or overscope the action → join never meets → comparison never runs (rule 6 killed).

**vs plan `D11`:** same defect class in a new shape. `D11` was hand-written **name pairs**. `object_claim` is hand-written **identity trees**. Richer structure (can encode inputs) does not add an independent check that the tree is right. It is not “names as standard math object”; it is a second authored namespace the join trusts.

### 3 · What superseding `F1` costs

- **Measurement:** **moved** from key collision to claim join when claims are right; **lost** when claims are wrong (above). Locator collision of different claims is a finding, not a value compare.
- **`D6` append-only vs plan `D5`:** **silently supersedes** the plan. Plan: each step *overwrites what it derives*; `step` is last writer. Artifact: re-derivation **appends** comparison and **does not replace** the imported value.  
  Literal dual-derivation consumer read (`02_…`):

  ```text

  derived_was 2
  ```

  Consumer of the merged export always reads the **first producer**. A later correct re-derivation never becomes the stored physics value.
- **Preventing a collision that should happen (rule 6):** yes — any claim-tree split that is finer than object identity (overscoped action, package label smuggled into “physics”, declaration history) prevents the meeting. That is F8’s cost relocated into claim authoring.

## Blocking findings

### B1 · Nothing checks claim **correctness**; join treats authored trees as ground truth

**What is wrong.** `object_claim` is the identity key for the whole design (`D2`–`D3`). Every guard assumes trees are right. Population (`D8`), schema (`D4`), value residual (`D5`), and import preservation (`D6`) never ask whether the tree names the right object.

**Mechanism.** Wrong shared claim → false meeting → payload equality ⇒ `AGREE` ⇒ publish. Wrong split claim → lost meeting ⇒ no `D5` ⇒ rule 6 dead. Same class as the 3,121-line name-pair defect: **hand identity without a check**.

**Literal output.** False meeting of different roles with equal payloads:

```text
FALSE_MEETING_via_wrong_claim
  meetings 1 values_equal True
  n_rows_should_be_2_if_claims_correct_but_got 1
  D8_population_check_sees_this NO
```

**What must become true.** Identity used for join must be checkable against something that is **not** the same authored artifact (e.g. a residual that moves when a named defining input is mutated — rule 14 form ablation), or the design must not put load-bearing identity in an unchecked tree.

---

### B2 · `D8` “independent required population” is not independent

**What is wrong.** `D8` says required claims come from the spec and MAIN sweep, independent of emitter and writer. In fact: (1) the claim **list** is builder-authored with the emitter; (2) root/stratum multiplicity is taken from **emitted orderings**.

**Mechanism.** Drop a root from `ROOT_ORDERING` and all its scoped tags before emission → required set shrinks with the emission → residual empty → missing mode invisible.

**Literal output.**

```text
OMISSION_VISIBLE_UNDER_D8_AS_WRITTEN False
OMISSION_VISIBLE_IF_REQUIRED_WERE_INDEPENDENT_OF_ORDERING True
SAME_AUTHOR_OMIT residual set()
```

**What must become true.** Omission checks that can be collapsed by the emitter’s own ordering are not omission checks. Fixed roles must not depend on the emitter; multiplicity must not be able to hide a deleted root by rewriting the ordering that defines the requirement.

---

### B3 · `D5` does not decide agreement on the committed type population

**What is wrong.** `D5` requires a structure-preserving residual per `value_kind` and agreement only when the residual establishes no difference. Committed data has **two** `value_kind`s and **many** structures. Literal `residual == 0` **fails for every matrix self-compare**; sequences/bools/predicates/text mostly **cannot subtract**; `FiniteSet` self-diff is `EmptySet`, not `0`.

**Mechanism.** Same-claim re-derivation of a matrix (dimensions, `M`, residuals) cannot reach `AGREE` under a naive reading → `UNDECIDED` → `D9` blocks publication even when values match; or a builder invents a non-residual channel that is not in the list (defaults/repairs forbidden by `D4`/`D12` tension).

**Literal output.**

```text
TOTAL 617
AGG_AGREE 578   # only if exact-no-sub is allowed as residual
AGG_UNDECIDED_OR_RULE_GAP 39   # all matrices under R==0
rows_where_self_sub_raises 488 of 617
rows_self_sub_works_but_R_ne_0 40
MATRIX_SELF_R_eq_0_count 0
MATRIX_SELF_R_eq_zeros_count 39
```

**What must become true.** For every admitted structure, one total channel that emits both operands and a residual that can establish “no difference” (including matrix/set/sequence/boolean), with `UNDECIDED` mapped to a defined non-silent action.

---

### B4 · `D9` makes genuine disagreement unpublishable

**What is wrong.** Publication requires all same-claim comparisons `AGREE`. Rule 6: disagreement is a finding. The merged export is how findings become chain state with operands (`F3`).

**Mechanism.** S10 and S11 derive the same claim with different values → `DISAGREE` → no published export → consumer never imports the comparison row → measurement does not enter the ledger.

**Literal output.** Design text + consumer simulation:

```text
D9_would_block_publish_on_DISAGREE True
consumer_value 1   # import kept under D6
derived_was 2
```

**What must become true.** A published artifact may carry `DISAGREE`/`UNDECIDED` comparisons with both operands; “complete MAIN run” and “all comparisons agree” must not be the same gate. Completeness ≠ consensus.

---

### B5 · `D6` append-only silently supersedes plan `D5` and freezes first-writer physics

**What is wrong.** Plan `D5`/`D7`: overwrite is how “current value” and knob retirement work. Artifact `D6`: import fields immutable; comparisons append only.

**Mechanism.** Wrong early value stays the only consumer-visible value forever if later claims differ (no meet) or if later agrees under a soft residual. If later disagrees under the same claim, `D9` blocks the whole publish (B4). Either way the chain does not get a corrected current object.

**Literal output.**

```text
plan_D5_said_overwrite_step_field_records_last_writer
artifact_D6_says_append_only_import_value_unchanged
consumer_value 1
derived_was 2
```

**What must become true.** Either the plan’s overwrite+last-writer semantics are restored for same-claim `AGREE`, with comparisons retained as history, or consumers are defined to read through `comparisons` — and that must be explicit, not a silent supersession.

---

### B6 · Claim join can lose meetings that should happen (rule 6)

**What is wrong.** Identity includes “exactly the named defining inputs.” Overall scale of `(T,W)` that leaves roots invariant is still a different claim if the action pair is in the tree → no meet.

**Mechanism.** Same mathematical root list from scale-related actions never compared.

**Literal output.**

```text
LOST_MEETING_via_overscoped_action_inputs
  claim_equal False
  meetings 0 n_rows 2
  payloads_equal_but_no_compare True
  D5_never_runs_on_them True
```

**What must become true.** Claim dependency scope must not vary with inputs the named object does not depend on (the measured F8/`F8d` failure, now on trees instead of keys).

## Bottom line

Superseding `F1` so keys are opaque is a reasonable response to three failed key-identity attempts. **Making `object_claim` the join key without any check on claim correctness recreates the hand-identity failure mode those attempts were circling.** Combined with D8’s emitter-tied population, D5’s incomplete residual rule, D6’s first-writer freeze, and D9’s “disagreement blocks publish,” the list does not yet make wrong export-chain physics reliably visible.

**What must become true before a builder is handed this list:** join identity that can be falsified; omission checks that cannot shrink with the emission; total agreement residual over admitted types; published records that can carry disagreement; explicit consumer semantics for multi-step derivation (overwrite vs append) that do not silently rewrite the plan.
