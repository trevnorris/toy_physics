## Findings

**1. The Wolfram harness prints "none found" for K6, K7 and K10 without looking for a witness (Claude Finding 1).
Confirmed; Grok's "confirms" on these three rows is wrong.**
- **What the code does.** The harness's `specs` give K6, K7 and K10 the kind `"ray"` (lookups, lines 201–208).
  The `searchWitness` branch for that kind builds a record and returns "none found" at once. The record holds the
  candidate parts, the profiles and the construction equations. The branch evaluates nothing (lines 213–225), and
  the harness calls no `Solve` or `FindInstance` anywhere.
- **What the method cannot print.** Every witness's `SitePart` is fixed to `"value"`, and `finiteExactQ` accepts
  only numbers. So the method cannot print a domain witness. Item 14 allows a domain witness, and it defines K10's
  site as the gate after negation.
- **What the record says.** The measurements file says "The search obtained no exact solution…" and calls these
  "finite unsuccessful searches" (line 18). No such search ran.
- **Grok's rows.** Grok's table marks Wolfram K6, K7 and K10 "none found; … tried printed | confirms". Printing the
  attempt record does not check whether an attempt was made.
- **The evidence that site parts are available.** The Claude leg's guarded script, at the harness's own printed
  profiles and point (three runs, exit 0), found two candidates:
  - for K6, a value part of `WL_LOCAL_S9B_RADAR_SLOPE_DERIVATION`, whose `Source` is the mutated `radarSource`
    (engine lines 356 and 375);
  - for K10, a domain part: `WL_LOCAL_S9B_NONRECIPROCAL_CONSTRUCTION` `Domain`, which contains the negated gate
    (engine lines 174 and 203).

  In each case both values are finite and exact and the two copies differ, with the attached conditions true. Those
  values stay in the leg's evidence and are not handed to the builder.
- **Required outcome.**
  - The Wolfram harness looks for a witness for K6, K7 and K10 as item 14 defines one, a value or a domain of a
    site part.
  - Where it prints "none found", the record of what was tried states only what was actually evaluated.
  - The round-8 measurements' description of these searches is replaced.
  - The harness reruns from the final code.

**2. The SymPy `SOFTWARE_CHECKS` line prints only true/false results (Claude Finding 2, minor). Verified; not
folded this round.**
- **The line.** It is new this round (line 663; absent at `9af9f705`). It prints each fixture's comparison with its
  expected result as a Boolean, then raises if any is false (lines 606–611 and 663–664). It does not print the
  fixture's computed mark or value.
- **Why it is not folded.** It changes no tag mark, witness, K11 pair or inventory field. Both legs re-derived every
  mark independently, so no claim rests on this line. The record will cite no software-check line.
- **Carried.** It departs from E1's emit-before-guard in a software self-test. If the SymPy harness is rebuilt for
  any other reason, it should print each fixture's computed mark or value before the guard.
